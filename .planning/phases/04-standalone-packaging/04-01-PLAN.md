## Phase Goal

Roadmap goal (verbatim, not in user-story form; see Flagged Assumptions in Plan 04-04): "Users other than the creator can download and run the app on macOS or Windows without installing Python or fighting OS security warnings."

This plan delivers the first slice: a Mac user can open a standalone `GDTF Comparer.app` that needs no Python. CI (04-02), first-launch instructions (04-03) and the public release (04-04) build out from it.

## Design notes (verified at planning time, 2026-10-14)

- This Mac: macOS 26.6.2 on arm64; shared venv Python 3.12.13 (Homebrew); `/usr/bin/codesign`, `/usr/bin/ditto` and `/usr/bin/lipo` present. `pip index versions pyinstaller` lists 6.22.3 as the latest version.
- `qt_material` 2.17 resolves `Path.home()` once, at import time, and `apply_stylesheet()` (called by `gui/theme.py` `install_os_theme` from `app.create_main_window`, before `MainWindow()` is built) writes recolored SVG icons into `Path.home()/.qt_material/theme/primary/`. If the theme XML or template is missing from the bundle, either the stylesheet is silently skipped (no icons) or the app crashes. Either way no icons appear. So "icons appeared under a fresh temporary home" is direct evidence that qt-material's hook bundled its data and that theming ran in the frozen app.
- `pygdtf` imports `pygdtf.utils`. Its `attr_loader` imports `attribute_definitions_data` inside a function and falls back to an `AttributeDefinitions.xml` file that does not exist in a frozen app. PyInstaller's bytecode scan should still collect that module, and Task 2 checks for it in the build output.
- `MainWindow` sets the window title "GDTF Comparer" (`gui/main_window.py`). `app.create_main_window` sets the application name "GDTF Comparer". PyInstaller's Windows error dialog is titled "Unhandled exception in script" (PyInstaller bootloader `pyi_exception_dialog.c`, Windows-only).
- `tests/test_architecture.py::test_no_network_modules_in_package` already guards the package source against network imports. This plan adds no package code.

<assumption_delta_decision>
Signal: singular to plural. One platform (run from source on the developer's machine) becomes two co-equal shipped platforms (D-04).
Current anchor: one entry point, `gdtf_comparer.app:main`.
Decision: keep one build definition and one check, and branch on `sys.platform` inside them. `packaging/app.spec` runs BUNDLE only on macOS. `packaging/smoke_check.py` resolves the per-OS executable path and runs the per-OS checks (codesign on macOS, window titles on Windows). The per-OS release names (`GDTF-Comparer-macos.zip`, `GDTF-Comparer-windows.zip`) are fixed in the Interfaces block below and shared by Plans 04-02, 04-03 and 04-04.
Rationale: two copies of the build configuration would drift silently (RESEARCH anti-pattern). D-04 already treats both OSes as equal, so nothing needs a promote/demote switch.
</assumption_delta_decision>
