## Phase Goal

**As a** lighting designer, **I want to** import an MVR show file, mark which attributes matter most for each fixture type, and share those requirements, **so that** anyone, including a rental shop checking their own inventory, can find substitute fixtures that meet them.

This plan's slice: "mark which attributes matter most for each fixture type". One type at a time (D-03), each with its own list (D-04).

## Design notes (verified at planning time, 2026-10-24)

- core.extract emits these numeric values:
  - Beam BeamAngle, FieldAngle, PowerConsumption, LuminousFlux and ColorTemperature (floats, keyed "Beam N" across files);
  - Physical Properties Weight (float, fixture level).
  Per-model Width/Height/Length never reach a requirement: compare() drops them from the cross-file view (Phase 3 G-03-3).
- Text values: BeamType (enum text) and the six DMX attribute-definition properties (Pretty, Feature, ActivationGroup, MainAttribute, PhysicalUnit, Color).
- requirement_options() (05-01) already filters to declared, non-None values. pygdtf backfills undeclared beam attributes (PowerConsumption 1000, LuminousFlux 10000, ...), and core.extract reports those as None, so they never become options. This plan adds the test that pins it.
- QDoubleSpinBox.setSpecialValueText("—") shows "—" while the value equals the minimum (0), which gives text rows a visible "no tolerance" box.
