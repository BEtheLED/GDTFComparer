## Design notes (verified at planning time, 2026-10-24)

- **pymvr 1.0.7 source.** Read from the researcher's downloaded wheel only. Nothing is installed: the shared venv reports pymvr NOT installed. Findings:
  - `GeneralSceneDescription(path)` hands `path` straight to `zipfile.ZipFile`, so an `io.BytesIO` works.
  - It is a context manager, and its exit closes its zip.
  - `scene` is set only when the root has a `<Scene>` child. Reading it otherwise raises AttributeError.
  - `ChildList` carries `fixtures`, `group_objects`, `scene_objects`, `focus_points`, `trusses`, `supports`, `video_screens` and `projectors`. `Fixture`, `SceneObject`, `Truss`, `Support`, `VideoScreen` and `Projector` each carry their own `child_list`.
  - `GDTFSpec` text is re-decoded UTF-8 to cp437, and gets a `.gdtf` suffix appended when it is longer than 5 characters and lacks one.
  - `FixtureIDNumeric`, `UnitNumber` and `CustomId` go through `int()` and raise a bare ValueError when malformed.
  - Its own XML parse is plain `xml.etree.ElementTree.fromstring`.
  - No declared dependencies, MIT license, author "vanous", repository github.com/open-stage/python-mvr: the same author and GitHub organization as the already-trusted pygdtf.
- **Minimal fixture XML.** `<Fixture name=".." uuid=".."><GDTFSpec>X.gdtf</GDTFSpec></Fixture>` is enough for pymvr. Every other child element is optional in its reader.
- **Hardening messages.** tests/core/test_hardening.py asserts phrases such as "not well-formed" and the file name. Generalizing the three helpers by a file-kind label plus a member name reproduces each GDTF message byte for byte when the label is "GDTF" and the member is "description.xml".
- **Architecture guard.** `APPROVED_CORE_SURFACE` must gain the three new GUI-facing core modules, and `PARSING_LIBRARY_TOP_LEVELS` gains "pymvr" so gui/ can never import it directly.
- **Row order and keys.** `core.comparator.compare(fixture, ())` returns rows in the same order the comparison table and Attributes panel use: Beam, then Physical Properties, then DMX categories in first-seen order. Beam keys are positional ("Beam 1") and there are no per-model dimension rows. Reusing it gives the editor its attribute order and gives candidates their value lookup, so requirement keys line up across manufacturers the same way comparison rows do (Phase 3 G-03-3). Using it means core/comparator.py needs no change at all.
- **Size.** This tracer is the phase's widest task (15 files). Each file gets only its happy-path essentials. The expansion plans own the depth, and the action names which plan owns what.

     - HIGHER: shortfall = target - candidate. LOWER: shortfall = candidate - target. Either way, GREEN when _at_most(shortfall, 0.0), YELLOW when _at_most(shortfall, amount), else RED.
     - CLOSEST: d = abs(candidate - target). GREEN when _at_most(d, amount * CLOSEST_GREEN_FACTOR), YELLOW when _at_most(d, amount * CLOSEST_YELLOW_FACTOR), else RED.
   - `CandidateScore` has count properties.
   - `score_candidate(requirement_set, candidate)`: build values = {row.key: row.target_value for row in compare(candidate, ()).rows}, so beams line up by position. Then values tuple = values.get(r.key) per requirement, and states = score_value per requirement.
   - `rank(scores)` sorts by (red_count, yellow_count, candidate.file_name.casefold(), candidate.file_name, candidate.source_path), a stable and deterministic order (D-11).
   - `scan_candidate_folder(folder, requirement_set, repository=None)`:
     - When requirement_set.requirements is empty, return CandidateScan(requirement_set, folder, (), ()) without loading anything.
     - names = os.listdir(folder). An OSError raises CandidateFolderError(f"Could not read the inventory folder '{folder}' ({exc.strerror}).") from exc.
     - Keep only names whose casefold ends with ".gdtf", sorted by (casefold, name).
     - Load each one with the repository: a model is scored with score_candidate; a GDTFError becomes CandidateFailure(path, exc.user_message).
     - Return CandidateScan(requirement_set, folder, rank(scores), tuple(failures)).
   - `scan_summary_message(scan)`:
     - No requirements: "This requirements file has no attributes marked important, so there is nothing to check."
     - Nothing found: "No GDTF files were found in '{folder}'."
     - Otherwise: "Checked {n} candidate(s) against {k} requirement(s) for '{fixture_name}'." plus " {m} file(s) could not be read." when there are failures.
   - `describe_requirements(requirement_set)`: f"{fixture_name} ({manufacturer})" (just the name when the manufacturer is blank), then " — {k} requirement(s): ", then ", ".join of f"{key.attribute} {format_value(target)} ({DIRECTION_LABELS[direction].lower()})".
   - Plan 05-03 owns requirement_options and the defaults. Plan 05-05 owns scoring, rank, scan and the messages.
