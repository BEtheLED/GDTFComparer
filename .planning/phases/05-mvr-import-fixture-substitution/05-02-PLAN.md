## Phase Goal

**As a** lighting designer, **I want to** import an MVR show file, mark which attributes matter most for each fixture type, and share those requirements, **so that** anyone, including a rental shop checking their own inventory, can find substitute fixtures that meet them.

This plan's slice: "import an MVR show file" works on the files LDs actually have. Fixtures can be nested in groups and trusses, names can be accented, a GDTF can be missing, and someone can pick the wrong file.

## Design notes (verified at planning time, 2026-10-24, from pymvr 1.0.7 source)

- `BaseChildNode._read_xml` re-decodes `<GDTFSpec>` text with `.encode("utf-8").decode("cp437")`. Python's zipfile writes non-ASCII member names with the UTF-8 flag and lists them as real Unicode, so "Lumière@Spot.gdtf" is listed correctly, while pymvr's string becomes mojibake. Reversing the transform (`encode("cp437").decode("utf-8")`) recovers the original text. For a zip written without the UTF-8 flag, zipfile itself decodes the raw name bytes as cp437, so the exact match already succeeds.
- Bare-exception sources inside pymvr (each wrapped by import_mvr's catch-all into MVRParseError):
  - `int()` on FixtureIDNumeric / UnitNumber / CustomId (ValueError)
  - `.decode("utf-8")` of the scene XML (UnicodeDecodeError, e.g. a Latin-1 encoded scene)
  - recursion on very deep nesting (RecursionError)
- tests/core/test_hardening.py::test_fifo_rejected_without_blocking is the pattern for a named-pipe test. tests/gui/test_shutdown.py::test_app_process_exits_when_worker_stuck_at_close is the pattern for the subprocess exit test.
