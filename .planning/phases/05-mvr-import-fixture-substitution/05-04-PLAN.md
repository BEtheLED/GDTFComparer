## Phase Goal

**As a** lighting designer, **I want to** import an MVR show file, mark which attributes matter most for each fixture type, and share those requirements, **so that** anyone, including a rental shop checking their own inventory, can find substitute fixtures that meet them.

This plan's slice: "share those requirements". The file that travels from the LD to the shop.

## Design notes (verified at planning time, 2026-10-24)

- `json.loads(..., parse_constant=f)`: f is called only for the NaN, Infinity and -Infinity tokens, so raising there refuses them. `object_pairs_hook` receives each object's key/value pairs in order, so a duplicate key can be detected and refused.
- `json.dumps(..., allow_nan=False)` (05-01) raises ValueError for a NaN or infinite float. The editor's spin boxes can't produce one, but a programmatic RequirementSet could, and save_requirements already maps that ValueError to RequirementsFileError.
- `type(x) is bool` must be checked before the number check, because bool is an int subclass in Python. This mirrors profile_repository's `type(version) is not int` check.
- Default `ensure_ascii=True` keeps the file pure ASCII ("Lumière"), so it survives any mail client or file share. json.loads restores the exact text.
