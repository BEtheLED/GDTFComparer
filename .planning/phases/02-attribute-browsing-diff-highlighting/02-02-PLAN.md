<objective>
Fill the Attributes panel with the fixture's full GDTF attribute vocabulary, end to end.

After Plan 02-01 the picker and compare() handle any category, but core.extract still only produces Beam and Physical Properties. This plan makes extraction also read every `<AttributeDefinitions><Attributes><Attribute>` entry: the fixture's DMX attribute vocabulary (Pan, Tilt, Dimmer, Zoom, Gobo1, ColorAdd_R and so on, commonly 60 to 150 per real moving light). Each definition becomes one checkbox in a "DMX: <feature group>" section, unchecked by default, and ticking it shows the definition's six properties compared across the files.

Purpose: ATTR-01 success criterion 1, "User can browse the full set of GDTF attributes (60+ properties) for a fixture, not just Beam and Physical Properties".
Output: attribute-definition extraction and a shared presence-check helper in core/extract.py, two category constants in core/models.py, an attributes_xml test-builder hook, and core plus real-run GUI tests.
</objective>

## Plan Goal

**As a** lighting professional comparing two moving-light fixtures, **I want to** see every DMX attribute each fixture defines (Pan, Tilt, Zoom, gobo and colour attributes and the rest) in the Attributes panel, grouped the way GDTF groups them, **so that** I can tick the ones that matter to me and compare them side by side instead of being limited to Beam and Physical Properties.

(ROADMAP Phase 2 goal, verbatim: "Users can browse and filter the complete set of GDTF attributes and see which values differ, instead of being limited to two hardcoded categories.")

## Design notes (verified at planning time)

Checks used the shared venv (pygdtf 1.4.5, PySide6 6.11.2) on the offscreen platform.

- **pygdtf reads definitions with the same lookups extraction will mirror.** FixtureType._read_xml runs `find("AttributeDefinitions")`, then `find("Attributes")`, then `findall("Attribute")`, and leaves `fixture_type.attributes == []` when either container is missing. A description.xml with no `<AttributeDefinitions>` at all loads through FixtureRepository with only the Weight key (measured).
- **What pygdtf does with each property (measured):** `name` and `pretty` are the raw XML text or None. `feature`, `activation_group` and `main_attribute` are always NodeLink objects: `.str_link` is the raw text or None, but `str(link)` of an omitted link is the four-letter word "None". `physical_unit` is an Enum: omitted gives `.value` None, a declared valid unit gives the text (including the valid unit "None"), and a declared unknown unit gives None. `color` is None when omitted, a ColorCIE when declared; `str(color)` is six-decimal "x,y,Y" text, and a malformed declaration falls back to the white point 0.312700,0.329000,100.000000.
- **Row shape.** The picker's selection unit is (category, attribute) (Plan 02-01, Research Pattern 2). So a definition's Name must be `AttributeKey.attribute`, which gives one checkbox per definition and makes it searchable by name. Each definition then has six rows, one per XML property, with the property name as `AttributeKey.element_path`. This mirrors Beam rows: element = the owning thing's instance or aspect, attribute = what the user ticks. The Element column reads "Feature", "PhysicalUnit" and so on for these rows.
- **Sections by GDTF feature group, with a fixed prefix.** GDTF files group attributes by FeatureGroup (Dimmer, Position, Gobo, Color, Beam, Focus, Control, Shapers, Video...). One flat "DMX Attributes" section with 60 to 150 entries would be the long list D-01 rules out. The group is the text before the first "." of the definition's Feature link. The "DMX: " prefix is required because GDTF's standard "Beam" feature group would otherwise share the legacy "Beam" category. That would merge the picker sections, and because "Beam" is in DEFAULT_SELECTED_CATEGORIES it would silently default-check every shutter, iris and zoom attribute.
- **No other file needs changing for the GUI.** Plan 02-01's compare() ranks LEADING_CATEGORIES first, then other categories in first-seen order. Its attribute_catalog() gives one leaf per (category, attribute), and its picker seeds only DEFAULT_SELECTED_CATEGORIES as checked. The new keys therefore arrive as unchecked, collapsed sections after Beam and Physical Properties.
- **Existing tests are unaffected.** make_gdtf today writes an empty `<Attributes/>`. With the new `attributes_xml=""` default it writes an empty `<Attributes></Attributes>`, so no existing test gains rows. BEAM_ATTRIBUTES and MODEL_ATTRIBUTES are only referenced inside core/extract.py (grep), so changing them from pairs to triples breaks no importer.
