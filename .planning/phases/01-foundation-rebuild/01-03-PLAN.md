pygdtf facts (verified from open-stage/python-gdtf source at planning time; confirm against the installed package): geometry nodes expose .name and a child list .geometries; beam nodes are pygdtf.geometries.GeometryBeam with .beam_angle, .field_angle, .power_consumption, .luminous_flux, .color_temperature (floats, spec defaults 25/25/1000/10000/6000 when omitted) and .beam_type (a value object with .value); fixture_type.models is a list of Model with .name, .width, .height, .length (floats, default 0).

Key-scheme decision (Claude's discretion under D-11, recorded here and in SKELETON.md): Beam keys use element_path = geometry names from the top-level geometry down to the beam joined by "/"; model keys use element_path = model name; Weight uses FIXTURE_LEVEL_PATH. RESEARCH Open Question 1 is resolved by NOT using pygdtf's get_geometry_tree()/iter_tree(): those expand GeometryReference instances per DMX mode (one beam definition becomes N instanced rows and a mode must be chosen), whereas the raw tree walk lists each defined beam once with a stable, human-readable path.
