<objective>
Expansion slice for RELI-01 + RELI-02 / roadmap success criterion 3: when a user picks a corrupt, non-GDTF, oversized or malicious file, the app shows a friendly message naming that file and stays usable — and hostile XML/zip input is rejected before pygdtf ever parses it.

Purpose: RESEARCH Pitfall 1 showed pygdtf silently substitutes a stub fixture for malformed XML and uses the unhardened stdlib parser, so relying on pygdtf's exceptions alone (D-12's assumption) cannot satisfy RELI-01. This plan adds the defusedxml + size-limit pre-validation (security measure, independent of structure validation, per D-12) inside FixtureRepository.load, wraps every failure in a typed GDTFError, and maps it to a plain-text dialog at the worker/thread boundary (D-14).
Output: core/errors.py, core/hardening.py, hardened core/repository.py, friendlier gui/worker.py + gui/main_window.py, and three test modules.

class GDTFError(Exception):             # __init__(self, path: str, reason: str)
    path: str; reason: str
