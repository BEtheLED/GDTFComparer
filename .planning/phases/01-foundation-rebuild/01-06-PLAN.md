## Decision Record: how "not specified" is detected (the 01-03 open decision)

01-03-PLAN.md surfaced this for a decision rather than guessing; the gap-closure orchestrator delegated that decision to this plan. Options weighed:

| Option | What the user sees for an omitted BeamAngle | Verdict |
|--------|---------------------------------------------|---------|
| (a) Accept pygdtf's spec defaults as the "effective" value and delete the dead `is None` branches | "25", indistinguishable from a file that declares 25; two files that both omit it compare as identical | Rejected: ships exactly the wrong-comparison bug the Core Value forbids |
| (b) Presence check over the validated description.xml tree; declared values from pygdtf, undeclared ones None ("N/A") | "N/A"; omitted vs declared-25 is flagged as differing | **Chosen** |
| (c) Keep the default but tag its provenance (e.g. "25 (GDTF default)") | "25 (default)" | Not now: needs a new provenance field on FixtureModel/ComparisonRow (the D-13 contract Phases 2-3 consume). The retained `FixtureModel.fixture_type` still carries pygdtf's defaults, so a later phase can add a hint without undoing (b) |

Why (b) needs no checkpoint: it reuses the existing `None` value that already renders as "N/A" (the whole-element-absent case since Plan 01-02). No new type, no on-disk or wire format, no change to the D-13 dataclass shapes, and the mechanism sits behind `extract_attributes`. Rated `costly` (flagged, not gated) because Phase 2 diff highlighting and Phase 3 CSV export will read "None = not declared" as a contract. D-09 is honoured (the pygdtf model is still wrapped, never flattened, and is the only source of values). D-12 is honoured: the lockstep alignment check is a consistency guard, not a schema or structure-validation layer.

Presence rules (verified at planning time against the installed pygdtf 1.4.5 source):
- Beam: `GeometryBeam._read_xml` reads the XML attributes `BeamAngle`, `FieldAngle`, `PowerConsumption`, `LuminousFlux`, `ColorTemperature`, `BeamType`, which are the same names as the GDTF names in `BEAM_ATTRIBUTES`. An attribute is declared when that name is a key of the paired `<Beam>` element's attributes.
- Model: `Model._read_xml` reads `Width`, `Height`, `Length`, the same names as in `MODEL_ATTRIBUTES`. Presence is checked on the paired `<Model>` element in the same way.
- Weight: `FixtureType._read_xml` does `find("PhysicalDescriptions")`, then `find("Properties")`, and `Properties._read_xml` does `find("Weight")` then reads `.attrib.get("Value", 0)`. Weight is declared only when that first-match chain finds a `<Weight>` carrying a `Value` attribute.
- Pairing: pygdtf builds geometry children, in document order, only from child elements whose tag is a key of `pygdtf.geometries.TAG_TO_GEOMETRY_CLASS`. That holds for both the `<Geometries>` collect and `Geometry._read_xml`. `GeometryReference` is a `BaseNode`, not a `Geometry`: it has no `geometries` attribute and pygdtf never descends into it. Models come from `find("Models").findall("Model")`. A prototype run in the planning scratchpad showed this filter keeps the two trees aligned across `GeometryReference`, `<Break>` and unknown-tag elements.
