## Design notes (verified at planning time)

All measurements were taken with the shared venv (PySide6 6.11.2, qt-material 2.17) on the offscreen platform with the qt-material theme applied. The table was also grabbed to PNG and inspected.

- The root cause is confirmed. qt-material's `QHeaderView::section` rule sets `text-transform: uppercase; padding: 0 24px`. Qt sizes a section from the model's text: "Category" gets 106 px, but "CATEGORY" plus padding needs 113 px (Element 101 vs 105, Attribute 105 vs 114). The rendered grab shows ":ATEGORY" and "ATTRIBUTI", which matches the user's screenshot.
- Widening sections after `resizeColumnsToContents()` by the uppercased label width plus 2 x 24 px (the UAT's suggested fix) makes the three fixed headers fit. It does not fix labels that must be elided. Qt elides the mixed-case string to fit the section and then paints it uppercase, so a capped, elided header still overflows and clips at both ends ("'ARGET: ASTERA_LED_TECH…" in the grab). G-01-2 needs a width cap, so this approach alone cannot close both gaps.
- Giving the header an all-uppercase font fixes both measuring and eliding. However, qt-material re-polishes widgets on a live light/dark switch, and that resets the header font to mixed case (verified). The fix would silently regress after the first appearance change.
- **Chosen:** a `QIdentityProxyModel` between the table model and the view that returns horizontal header DisplayRole text already uppercased. Qt's own size hint and elision then work on exactly the text qt-material paints. Measured results: Category/Element/Attribute sections become 119/119/122 px (need 113/105/114). A 280 px target header rendered "TARGET: ASTERA_…STERA___V3.GDTF" with no clipping in both themes. Section sizes were identical before and after a live light-to-dark switch, and ToolTipRole passes through unchanged. The acceptance test uses the UAT's own measure: section width at least the uppercased label advance plus 2 x 24 px. There is no custom QSS and the vendored template is not edited (D-05, D-08).
- In PySide6 6.11.2, QHeaderView's default text elide mode is ElideNone, so middle elision must be set explicitly. qt-material honours it.
- A width cap applied as a per-section clamp with `resizeSection` after `resizeColumnsToContents()` still lets the stretched last section fill the viewport: the horizontal scrollbar maximum was 0 at both 1000 px and 1600 px window widths. It also lets the user drag a column wider. A header-wide maximum section size would block that drag, which matters because dragging is the way to read a long name in full.
- The UAT's second fix option ("clamp after resizeColumnsToContents()") is the one used. Middle elision rather than end elision is Claude's discretion: GDTF-Share file names end with the revision (`…@V2.gdtf` / `…@V3.gdtf`), and that ending is what tells same-named columns apart.
- Label content (Claude's discretion): the header label is the fixture's `name` only. The manufacturer moves into the header tooltip, next to the full path that was already there. Most fixture names fit inside 280 px on their own (a 280 px header holds about 27 uppercase characters). A "Manufacturer Name" label would push most headers into elision. When names collide, the file-name fallback still carries the manufacturer, because GDTF file names start with it.
