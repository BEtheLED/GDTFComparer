<objective>
Close two gaps diagnosed in 03-UAT.md during Phase 3's whole-phase walkthrough.

G-03-1 (major, bug): the profile toolbar row (profile_combo, save_profile_button, manage_profile_button) is squeezed into one QHBoxLayout inside the 260 px Attributes panel. qt-material's uppercase + heavy padding/chrome inflates each widget past its third of the row, and none of them elides, so the user saw "No si▾" / "AVE." / "M...e" instead of the real labels. Fixed by splitting the one row into two stacked rows (dropdown alone, then Save…+Manage) -- measured at planning time to resolve the clipping with every widget's full label intact, at both the panel's 260 px default and its (slightly raised) drag floor.

G-03-2 (minor, new feature approved during UAT): the "Compare with" list gains a per-file colored-dot indicator showing whether that file matches the target in the currently checked attributes, reusing ComparisonRow.differs/any_differs with no new comparison logic. It only has data once Run Comparison has produced a result, and resets to a neutral "not yet compared" state whenever the target, the file list, or the checked attributes change.

Purpose: ATTR-03's compare-profiles workflow depends on the Attributes panel toolbar being legible (G-03-1), and the user explicitly asked for the match indicator as a direct extension of the same go/no-go substitute-fixture workflow the profiles feature serves (G-03-2; 03-CONTEXT.md D-01).
Output: a two-row profile toolbar in gui/main_window.py plus a raised panel drag floor; a per-item match-state dot, tooltip and data role on the "Compare with" list, wired through the four places that must invalidate it; two updated existing tests; one new test file.
</objective>

## Design notes (verified at planning time)

Measurements were taken with the shared venv (PySide6 6.11.2, qt-material) on the offscreen platform, with `dark_blue.xml` applied via `qt_material.apply_stylesheet`, instantiating the real `MainWindow`.

**G-03-1, confirming the root cause.** With the panel at its current 260 px default, `attributes_group.contentsRect().width()` is 224 px. The three widgets' `sizeHint().width()` are: `profile_combo` 122 px (placeholder "No saved profiles yet", `AdjustToMinimumContentsLengthWithIcon` + `setMinimumContentsLength(8)`), `save_profile_button` 78 px ("Save…", qt-material's uppercase + padding chrome), `manage_profile_button` 92 px ("Manage" + menu-indicator arrow chrome). Total needed is 292 px plus inter-widget spacing, against 224 px available -- Qt's `QHBoxLayout` falls back to squeezing all three down to roughly equal thirds (measured: 65 px, 65 px, 64 px), which is exactly the reported clipping.

**G-03-1, the fix, measured.** Splitting into two stacked rows -- row 1: `profile_combo` alone with stretch 1; row 2: `save_profile_button` and `manage_profile_button`, each with stretch 1 -- gives, at the unchanged 260 px default: `profile_combo` 206 px (>= 122 needed), `save_profile_button` 108 px (>= 78), `manage_profile_button` 92 px (== 92, its sizeHint exactly, zero clip). At the panel's current 220 px drag floor, the same two-row layout still shrinks `manage_profile_button` below its sizeHint (82 px measured, 10 px short). Re-measuring at increasing floors found the exact breakeven: at a 230 px group width both buttons land exactly on their sizeHint (save 78/78, manage 92/92); at 236 px save gets 84/78 and manage stays pinned at 92/92; at 240 px save gets 88/78 and manage stays pinned at 92/92. `manage_profile_button` never grows past its own sizeHint even with extra room, so once the floor clears 230 px nothing ever clips. **Chosen: raise `attributes_group`'s minimum width from 220 to 240 px** (`ATTRIBUTES_PANEL_MIN_WIDTH_PX`), 10 px above the measured breakeven for margin against font-metric variance across platforms. No existing test asserts the old `220` value (confirmed by grep).

**G-03-1, the path not taken.** 03-UAT.md's other candidate -- icon-only Save/Manage buttons with the label moved to a tooltip -- was measured to also fit, but was rejected: it hides the words "Save…" and "Manage" behind icons, which is harder for a non-technical user to parse at a glance than two clearly labeled buttons stacked below the dropdown. The stacked-rows option keeps every label exactly as it reads today.

**G-03-1, no change to the default.** `content_splitter.setSizes([260, 1020])` is untouched; only the floor the user can drag down to moves from 220 to 240.

**G-03-2, the match semantics.** `core.comparator.compare()` already produces, per `ComparisonRow`, a `differs` tuple aligned to `ComparisonResult.comparisons` order -- `row.differs[i]` is `True` when comparison file `i` disagrees with the target for that row's `(category, attribute)`. `attribute_picker.checked_attributes()` is the exact same set that already drives which rows the results table shows (D-03, Phase 2). So "file `i` matches" is simply: no row whose `(category, attribute)` is in the checked set has `differs[i] == True`. This needs no new field on `ComparisonRow`, no new core function, and no change to `core/`.

**G-03-2, why resets are needed, and why they must be explicit for the target.** `self.table_model.result()` keeps showing the OLD result until the next Run Comparison finishes -- changing the target file does not clear it. If the dots were only ever recomputed from the live result (never force-reset), changing the target would leave the OLD comparison's colors on screen, now describing a target that is no longer selected. `set_target_file`, `add_compare_files` and `remove_selected_files` must therefore force every dot back to the neutral "unknown" state directly, not merely rely on a recompute noticing something changed.

<assumption_delta_decision>
Signal: measured contradiction. 03-CONTEXT.md D-07 says "Save and Manage ... sit in the same compact toolbar row ... alongside the load dropdown" -- the literal one-row reading of that sentence is exactly what 03-UAT.md G-03-1 reports as broken: three widgets whose combined sizeHint (292 px) cannot fit the panel's available content width (224 px), with none of them eliding, so all three got clipped.
Current anchor: the Attributes panel is fixed at 260 px by default (`content_splitter.setSizes([260, 1020])`) and has a drag floor (`attributes_group.setMinimumWidth(...)`); neither the panel's existence nor its default width changes.
Decision: adapt. Keep all three controls in one consolidated toolbar block immediately above the picker -- D-07's actual intent, "one consolidated location for all profile actions" -- but split that block into two stacked rows instead of one: the dropdown alone, then Save…+Manage below it. Raise the panel's drag floor from 220 to 240 px so the split never clips even at the floor.
Rationale: measured at planning time (Design notes above). Every widget gets at least its own sizeHint width, in both qt-material themes, at both the 260 px default and the new 240 px floor. This is the literal "split into two stacked rows" option 03-UAT.md's own `missing` field offered, chosen over icon-only buttons because it keeps every label as readable text, consistent with this project's non-technical-user-facing wording throughout (03-CONTEXT.md D-06, D-04's confirm-dialog wording, etc.).
</assumption_delta_decision>
