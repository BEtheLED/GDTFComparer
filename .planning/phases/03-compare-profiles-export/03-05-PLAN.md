<objective>
Close gap G-03-3 (major) from 03-UAT.md: "I don't think that it is actually looking at more than 1 GDTF file as any other file I add just says NA."

Every file IS parsed correctly. The defect is in how rows are lined up across files: core.comparator.compare() matches rows by the exact AttributeKey (category, element_path, attribute), and for Beam rows element_path is each file's own manufacturer-chosen geometry path, for dimension rows each file's own model name. Different fixtures almost never share those names, so every comparison column reads N/A on the target's rows while the comparison file's real values land on separate rows further down (full evidence: .planning/debug/comparison-engine-only-reads-target-file.md).

The user made both product decisions on 2026-10-07 (STATE.md, 03-UAT.md G-03-3 `decision`); they are locked, not re-decided here:
1. Beam-level rows match across files by POSITION (1st beam vs 1st beam, 2nd vs 2nd, ...); a file with fewer beams shows a genuine N/A at the missing position.
2. Per-model physical-dimension rows (Width/Height/Length per mesh part) are dropped from cross-file comparison entirely -- scoped to the comparison table only; extraction and storage are unaffected.

Purpose: Phase 3 D-01's primary workflow -- one spec-sheet profile run against fixtures from other manufacturers -- is unusable while every comparison column reads N/A; this also makes the G-03-2 match dots meaningful again (they read "different" for everything because of the same misalignment).
Output: a cross-file view in core/comparator.py that compare() builds rows from; a new app-level regression test module; new core regression and boundary tests; existing tests that pinned the old exact-name assumption rebaselined to the new contract.
</objective>

**Blast radius, measured.** The full suite (258 tests, ~13 s) run with the prototype compare() swapped in produced exactly 10 failures, all tests that pinned the old exact-name keying or the old row count that included dimension rows -- no behavioral regression anywhere else (DMX, profiles, highlighting, headers, architecture, extraction all pass):

- tests/gui/test_attribute_selection.py: `test_picker_lists_default_categories_checked`, `test_unchecking_attribute_hides_its_rows`, `test_selection_survives_rerun`, `test_no_attributes_checked_shows_empty_table_and_hint`, `test_search_does_not_change_table_rows` (19/17 row counts include six dimension rows; one `"Body/Head1/Beam"` lookup).

- tests/gui/test_namespaced_rows.py: `test_table_shows_distinct_element_paths` (`"Body/Head1/Beam"` lookups, expects a `"Head"` Width row).
- tests/gui/test_unspecified_values.py: `test_omitted_beam_attribute_cell_reads_na` (`"Head/Beam"` lookup).
These eight GUI tests are rebaselined in Task 2.

**Probes, measured RED today and GREEN with the prototype:** document order beats alphabetical order (top-level `Zed` beam before `Alpha` beam -> `Zed` is Beam 1); two beams both named `Beam` under one parent (extracted as `Body/Beam` and `Body/Beam#2`) get positions 1 and 2; a dimension-only pair of files yields exactly one Physical Properties row (`Weight`) while `AttributeKey("Physical Properties", "Head", "Width")` is still in `result.target.attributes`; in MainWindow a same-values/different-names file gets `MATCH_STATE_MATCH` and a different-BeamAngle file gets `MATCH_STATE_DIFFERS`; a profile `{(Physical Properties, Weight), (Physical Properties, Width)}` loaded after a run reports `"1 of 2 spec items in 'Spec' weren't found in these files: Width."`.

**Why compare() and not extract.py.** Re-keying beams positionally inside extraction would also work for matching, but it would change what AttributeKey.element_path means for every FixtureModel (documented as a geometry path), rewrite a dozen Phase 01 extraction tests, and contradict the decision's own scoping ("do not change how these are extracted/stored"). A per-model cross-file view built inside compare() changes only cross-file row identity, keeps D-11 within-file keys intact on FixtureModel.attributes, and needs zero GUI changes: the table shows `key.element_label` (now "Beam N"), the picker catalog is derived from rows, and the dots read `differs`.
