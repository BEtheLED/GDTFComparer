<objective>
When a saved spec sheet is loaded against fixture files that do not have some of its items, tell the user plainly how many items, and which ones, were not evaluated (Phase 3 D-06). The check is redone after every re-run, so swapping in a different candidate fixture is checked fresh.

Purpose: ATTR-03's "reload it for future comparisons" in the D-01 workflow, where profiles are routinely loaded against fixtures with a very different attribute set. The user makes go/no-go sourcing calls from this, so a shorter list must never look like a full pass.
Output: missing_attributes() in core/profile_repository.py; a not-found branch in MainWindow._show_result_status plus a "run a comparison" message for a profile loaded before any comparison; tests/gui/test_profile_portability.py and a core unit test.
</objective>

## Phase Goal

**As a** lighting/AV professional checking whether a substitute fixture measures up, **I want to** save the attributes I care about as a named spec sheet and reload it against any fixture files, **so that** I can see at a glance whether a candidate has what I need, without re-ticking attributes or emailing back and forth with a vendor.

(ROADMAP Phase 3 goal, verbatim: "Users can save and reload reusable attribute selections ("compare profiles") for future comparisons." The story is assembled from 03-CONTEXT.md D-01 and the user's quoted scenario.)

## Design notes

- **Why a persistent branch, not a one-shot message.** Loading calls AttributePicker.set_checked, which starts the 0 ms coalescing timer. On the next event-loop turn selection_changed runs _apply_attribute_selection, which ends in _show_result_status. A status message written directly by the load handler would be overwritten immediately whenever a result exists. Putting the report inside _show_result_status, keyed on MainWindow._active_profile (set in Plan 03-01 on load and save), makes it survive that emission and makes every re-run (on_comparison_ready, then _apply_attribute_selection) recompute it against the new catalog.
- **What counts as missing.** spec = _active_profile.attributes intersected with attribute_picker.checked_attributes(). available = every (category, attribute) in attribute_catalog(result), which is the union of rows across the target and all comparison files, so "missing" means no file has it, exactly D-06's wording. missing = missing_attributes(spec, available). Missing items are never rendered in the picker tree (they are not in the catalog), so the user cannot untick them by accident; they stay in the checked set until another profile is loaded.
- **Precedence inside _show_result_status** (after the existing "result is None: return"):
  1. not-found text present, and "Show differences only" empties a non-empty selection: show not-found text + " " + NO_DIFFERENCES_MESSAGE.
  2. not-found text present: show it alone. This replaces NO_ATTRIBUTES_SELECTED_MESSAGE, which would be false here, because spec items ARE checked and just absent.
  3. otherwise the existing Phase 2 chain, unchanged.
- **No result yet.** _show_result_status returns early while table_model.result() is None (no comparison yet, or one is running), so a message written by the load handler in that state is not overwritten. When the result arrives, the branch above computes the report.
