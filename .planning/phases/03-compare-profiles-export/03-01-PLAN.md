## Design notes (verified at planning time)

Checks used the shared venv (Python 3.12, PySide6 6.11.2) on the offscreen platform, with `warnings.simplefilter("error", DeprecationWarning)`. Baseline: the full suite passes (159 passed in about 12 s).

- **Two Phase 1 architecture guards change RESEARCH's design.** First, `tests/test_architecture.py::test_core_never_unpacks_archives_or_uses_temp_dirs` fails if any core module imports `tempfile` or `shutil`, so RESEARCH's `tempfile.mkstemp` write cannot be used. The temp file is opened with `os.open(path, O_WRONLY | O_CREAT | O_EXCL | O_BINARY-if-present, 0o600)` under a random `os.urandom(8).hex()` name in the same folder, then fsynced and moved over the old file with `os.replace`. The atomicity is the same, and the guard is kept. Second, `test_gui_uses_only_core_service_surface` lets gui/ import only `core.comparator`, `core.models` and `core.errors`, so this plan adds `gdtf_comparer.core.profile_repository` to `APPROVED_CORE_SURFACE`.
- **QComboBox with a placeholder (measured).** With `setPlaceholderText(...)` set, `addItems`, and `clear()` followed by `addItem`, both leave `currentIndex() == -1`, so the placeholder shows until code selects an index. A programmatic `setCurrentIndex(1)` does NOT emit `activated` (RESEARCH A3 confirmed). `combo.activated.emit(0)` from Python reaches a connected slot, so tests can simulate a user choice.
- **QMessageBox (measured).** `clickedButton()` is `None` before `exec()`. Comparing `box.clickedButton() == box.button(QMessageBox.StandardButton.Yes)` works. Patching `QMessageBox.clickedButton` on the class makes that comparison controllable in tests. `setDefaultButton(QMessageBox.StandardButton.No)` makes `defaultButton()` equal `button(No)`.
- **Default-seeding interaction (read from code).** `AttributePicker.set_catalog` checks every never-seen pair in `DEFAULT_SELECTED_CATEGORIES` (Phase 2 D-04). In the D-01 workflow (open the app, load a spec sheet, then compare an unrelated fixture), every catalog pair is new on the first run, so without a change the Beam / Physical Properties defaults would be added to the loaded spec sheet. `set_checked` therefore turns default seeding off for the rest of the session (`_defaults_enabled = False`).
- **Status bar ownership.** `_show_result_status()` stays the single writer of the result status. This plan only adds event messages: "Saved profile …" after a save, and the startup "profiles unavailable" message. Plan 03-02 adds the D-06 not-found branch.

Rationale: both guards protect real Phase 1 properties (no temp-dir unpacking; a curated GUI-to-core surface). The first is satisfied without weakening it. The second is a curated list meant to grow when a new core service appears.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local disk (profiles.json in the per-user app-data folder) -> ProfileRepository.load_all | The file may be damaged, hand-edited, truncated, huge, or written by a newer app version; it is untrusted input to the parser |
| User keyboard -> QInputDialog profile name -> core | Free text from the local user; validated before it is stored and never used as a path |
| ProfileRepository._write_all -> filesystem | A crash, a full disk or a permission error can interrupt any write |
